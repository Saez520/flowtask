# Plan Template

Standard structure for all implementation plans generated by FlowTask.

---

## Structure

```markdown
# {Plan Title}

## TL;DR
> **Summary**: 1-2 sentences
> **Deliverables**: bullet list
> **Effort**: Quick | Short | Medium | Large | XL
> **Parallel**: YES - N waves | NO
> **Critical Path**: Task X → Y → Z

## Context
### Original Request
### Interview Summary
### Metis Review (gaps addressed)

## Work Objectives
### Core Objective
### Deliverables
### Definition of Done
### Must Have
### Must NOT Have (AI-slop patterns, scope boundaries)

## Verification Strategy
> ZERO HUMAN INTERVENTION — all verification is agent-executed.
- Test decision: TDD / tests-after / none + framework
- QA policy: Every task has agent-executed scenarios
- Evidence: {evidence-path}/task-{N}-{slug}.{ext}

## Execution Strategy
### Parallel Execution Waves
> Target: 5-8 tasks per wave. <3 per wave (except final) = under-splitting.
> Extract shared dependencies as Wave-1 tasks for max parallelism.

Wave 1: [foundation tasks with categories]
Wave 2: [dependent tasks with categories]
...

### Dependency Matrix (full, all tasks)

## TODOs

- [ ] N. {Task Title}

  **What to do**: clear implementation steps
  **Must NOT do**: specific exclusions

  **Recommended Agent Profile**:
  - Category: `{name}` — Reason: why
  - Skills: [`skill-1`] — why needed

  **Parallelization**: Can Parallel: YES/NO | Wave N | Blocks: [tasks] | Blocked By: [tasks]

  **References** (be exhaustive):
  - Pattern: `src/path:lines` — what to follow and why
  - API/Type: `src/types/x.ts:TypeName` — contract to implement
  - Test: `src/__tests__/x.test.ts` — testing patterns

  **Acceptance Criteria** (agent-executable only):
  - [ ] verifiable condition with command

  **QA Scenarios** (MANDATORY):
  ```
  Scenario: Happy path
    Tool: [Playwright / bash / curl]
    Steps: exact actions with specific data/commands
    Expected: concrete, binary pass/fail
    Evidence: {evidence-path}/task-{N}-{slug}.{ext}

  Scenario: Failure/edge case
    Tool: [same]
    Steps: trigger error condition
    Expected: graceful failure
    Evidence: {evidence-path}/task-{N}-{slug}-error.{ext}
  ```

  **Commit**: YES/NO | Message: `type(scope): desc` | Files: [paths]

## Final Verification Wave
> 4 review agents run in PARALLEL. ALL must APPROVE.
- [ ] F1. Plan Compliance Audit
- [ ] F2. Code Quality Review
- [ ] F3. Real Manual QA
- [ ] F4. Scope Fidelity Check

## Commit Strategy
## Success Criteria
```

---

## Key Rules

- **Single Plan Mandate**: Everything goes into ONE plan. 50+ tasks is fine.
- **Implementation + Test = ONE task**: Never separate.
- **Every task MUST have**: Agent Profile, Parallelization, References, Acceptance Criteria, QA Scenarios.
- **QA Scenarios**: Specific tool + concrete steps + exact assertions. Both happy-path AND failure.
- **Evidence files**: Every QA scenario produces an evidence file.
